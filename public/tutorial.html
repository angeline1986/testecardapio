Guia de atualização do cardápio

Atualize, confira e publique com tranquilidade.

Este guia acompanha o processo completo: abrir os arquivos do projeto, ajustar o cardápio, ver como ficou e enviar a versão aprovada para o site.

Ver as etapas ↓ Abrir estatísticas ↗
✦
O fluxo é simples: editar → conferir → publicar.

Não há uma etapa de “build” separada. O próprio comando de publicação prepara os arquivos e envia o site.

1. Abrir o projeto2. Conferir a prévia3. Fazer alterações4. Publicar5. Estatísticas6. Guardar alterações
1
Uma vez por computador

Abrir o projeto e preparar o ambiente

O projeto é a pasta com os arquivos do cardápio. Abra o aplicativo Terminal (no Mac, pressione Command + Espaço, digite “Terminal” e pressione Enter).

Se a pasta do projeto já está no computador, digite cd no Terminal, arraste a pasta do projeto para a janela e pressione Enter. Depois, inicie a verificação:

./setup_cardapio.command

O assistente verifica se o computador tem os programas necessários e explica se faltar algo. Para abrir a prévia, também é necessário ter Python 3 instalado. Siga as instruções que aparecerem na tela.

É a primeira vez neste computador?

Baixe uma cópia do projeto com estes comandos. Depois, abra a pasta criada chamada testecardapio no Terminal e rode o assistente acima.

git clone https://github.com/angeline1986/testecardapio.git cd testecardapio
O assistente pediu para conectar à Cloudflare?

Esse acesso é necessário para publicar o site. Rode o comando abaixo; uma página da Cloudflare abrirá para você entrar e autorizar a conexão. Depois, volte ao Terminal.

npx wrangler login
2
Antes de publicar

Conferir uma prévia do cardápio

Com o Terminal aberto na pasta do projeto, rode:

./preview.command

O navegador abrirá o cardápio no seu computador. Essa versão serve para revisão e só você consegue acessá-la. Deixe a janela do Terminal aberta durante a conferência.

Para encerrar: volte ao Terminal e pressione Control + C. A prévia não altera nem publica o site.

3
Faça uma alteração por vez

Atualizar produtos, fotos e aparência

Abra a pasta do projeto em um editor de texto ou de código (por exemplo, Visual Studio Code). Os arquivos mais usados são:

  • Produtos e preços: public/products.json.
  • Fotos: public/assets/chef-dani/. Ao adicionar uma foto nova, atualize também o nome do arquivo no cadastro do produto.
  • Página e visual: public/index.html (conteúdo), public/style.css (aparência) e public/script.js (interações).

Salve o arquivo, atualize a prévia no navegador e confira o resultado em computador e celular. Antes de publicar, confirme especialmente os nomes, preços, fotos e disponibilidade.

O cardápio deste site é atualizado separadamente. Mudanças feitas no InstaDelivery não aparecem aqui sozinhas.

4
Esta etapa altera o site público

Enviar a versão aprovada para o site

Quando terminar a revisão, volte ao Terminal e rode:

./deploy.command

O comando confere os arquivos e a conexão com a Cloudflare antes de publicar. Quando terminar, abra o site e confirme que a atualização apareceu: cardapio.chefdaniteles.workers.dev ↗

Sobre “build”: não precisa procurar outro botão nem rodar um comando separado. O script cuida da preparação e do envio.

Se o Terminal mostrar uma mensagem de erro, o site não foi atualizado por esse comando. Leia a mensagem: ela costuma indicar o próximo passo. Se disser que falta entrar na Cloudflare, rode npx wrangler login e tente de novo.

5
Acesso administrativo

Consultar as estatísticas

Abra o painel e entre com a senha administrativa:

Abrir o painel de estatísticas ↗

O painel reúne visitas e ações feitas no cardápio. Escolha o período disponível para comparar os dados.

Esqueceu a senha ou precisa ver os registros técnicos?

A senha pode ser alterada por quem tem acesso administrativo à conta Cloudflare. No Terminal, dentro da pasta do projeto, rode o comando abaixo e digite a nova senha quando solicitado. Ela não aparece na tela enquanto você digita; isso é normal.

npx wrangler secret put ADMIN_PASSWORD

Para suporte técnico, os registros recentes podem ser vistos com:

npx wrangler tail cardapio

6
Guardar uma cópia das alterações

Sincronizar com o GitHub

O GitHub guarda o histórico do projeto e permite recuperar alterações. Depois de conferir tudo, rode os comandos abaixo. Troque a frase entre aspas por um resumo, como Atualiza preços dos bolos:

git status git add -A git commit -m "Atualiza produtos do cardápio" git push origin main

O primeiro comando mostra quais arquivos mudaram. O último envia as alterações ao GitHub. Neste projeto, isso pode iniciar uma publicação automática; o comando ./deploy.command é a forma manual de publicar.

Se o Terminal disser que não há alterações para registrar, tudo bem: não há mudanças novas para sincronizar.
