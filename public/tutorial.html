Guia para Windows

Atualize, confira e publique com tranquilidade.

Siga as etapas na ordem. Você vai abrir a pasta do projeto, alterar o cardápio, conferir a mudança numa cópia de teste e só então atualizar o site que os clientes acessam.

Primeiro confira. Depois publique.

A prévia é uma cópia de teste no seu computador. O site público só muda quando você executa a etapa “Publicar”. Não há um comando separado para “build”.

Como usar os comandos deste guia

Cada caixa escura contém um comando. Clique em Copiar, clique na janela do Git Bash, clique com o botão direito para colar e pressione Enter. Espere o comando terminar antes de colar o próximo. Não cole comandos na barra de endereço do navegador.

O tutorial está dividido em páginas

Use o índice à esquerda para abrir uma etapa específica. Os botões no fim de cada página também levam para a etapa anterior ou seguinte.

1
Preparação — faça uma vez neste computador

Instalar os programas necessários

O projeto usa três programas gratuitos. Instale-os antes de continuar:

  • Git for Windows — inclui o Git Bash, a janela onde você vai colar os comandos. Durante a instalação, mantenha as opções padrão e confirme que Git Bash Here está selecionado. Baixar Git for Windows ↗
  • Node.js — na página, escolha a versão marcada como LTS e instale usando as opções padrão. Baixar Node.js ↗
  • Python 3 — necessário para abrir a prévia do cardápio no computador. Baixar Python para Windows ↗

Depois de instalar, feche e abra novamente o Git Bash para que ele reconheça os programas.

Abrir o projeto no Git Bash

O Git Bash é uma janela de comandos instalada junto com o Git for Windows. Use o Git Bash para executar os comandos deste guia.

Se a pasta do projeto já existe: abra o Explorador de Arquivos, localize e abra a pasta testecardapio. Clique com o botão direito em uma área vazia dentro da pasta e escolha Git Bash Here (ou Mostrar mais opções → Git Bash Here). Uma janela do Git Bash abrirá já na pasta correta.

Se ainda não baixou o projeto: abra o menu Iniciar, procure Git Bash e abra o aplicativo. Execute os dois comandos abaixo, um de cada vez, na ordem. O primeiro baixa o projeto e o segundo entra na pasta baixada:

git clone https://github.com/angeline1986/testecardapio.git
cd testecardapio

Agora verifique se o computador está pronto. Na janela do Git Bash aberta dentro da pasta do projeto, copie este comando, cole com o botão direito e pressione Enter:

./setup_cardapio.command

O Git Bash vai mostrar uma lista de itens. ✓ significa que o programa está pronto. ✗ significa que ele não foi encontrado: instale o programa indicado, feche e abra o Git Bash e repita essa verificação.

Não aparece a opção “Git Bash Here” no Explorador de Arquivos?

O Git Bash não foi adicionado ao menu do botão direito. Execute novamente o instalador do Git for Windows e habilite a opção Git Bash Here na integração com o Explorador de Arquivos. Depois, feche e abra o Explorador de Arquivos e tente de novo.

O assistente fez uma pergunta e não sei o que responder

Se perguntar Configurar senha administrativa agora? [s/N], responda N se você não for a pessoa responsável pela senha do painel. Se for responsável, responda s e digite a nova senha quando solicitado; os caracteres não aparecem enquanto você digita, e isso é normal.

Se perguntar Executar validação/publicação do cardápio agora? [s/N], responda N por enquanto. A publicação tem uma etapa própria mais abaixo, depois da revisão da prévia.

Se informar que falta um segredo chamado SESSION_SECRET, não tente adivinhar um valor: peça ajuda à pessoa responsável pela conta Cloudflare antes de publicar.

O Git Bash diz que não está conectado à Cloudflare?

A Cloudflare é o serviço onde o site está publicado. Copie e execute o comando abaixo. Uma página abrirá no navegador: entre na conta Cloudflare responsável pelo cardápio e autorize o acesso. Depois volte ao Git Bash e execute novamente ./setup_cardapio.command.

npx wrangler login
2
Faça isso sempre que for revisar mudanças

Conferir uma prévia do cardápio

Confirme que a janela do Git Bash está aberta na pasta testecardapio. Copie o comando, cole com o botão direito e pressione Enter:

./preview.command

O navegador deve abrir uma página com o cardápio. O endereço começa com http://127.0.0.1; isso significa que você está vendo a cópia de teste no seu computador. Se o navegador não abrir sozinho, copie o endereço que apareceu no Git Bash e cole-o na barra de endereço do navegador.

Depois de editar um arquivo, volte para essa página e atualize-a com Ctrl + R para ver a mudança. Mantenha a janela do Git Bash aberta enquanto estiver usando a prévia.

Para fechar a prévia: clique na janela do Git Bash e pressione Ctrl + C. Isso fecha só a cópia de teste; não publica nem apaga nada.

3
Salve o arquivo e confira a prévia depois de cada mudança

Atualizar produtos, fotos e aparência

Use um editor de código, como o Visual Studio Code. No VS Code, escolha File → Open Folder (Arquivo → Abrir Pasta), selecione a pasta testecardapio e clique em Select Folder (Selecionar Pasta). Os arquivos do projeto aparecem na coluna esquerda. Para atualizar um produto:

  • Na coluna esquerda, clique na seta ao lado de public e depois em products.json.
  • Pressione Ctrl + F, escreva o nome atual do produto e pressione Enter para encontrá-lo.
  • Altere apenas o texto ou número entre aspas indicado abaixo. Não apague aspas, vírgulas ou chaves: elas são necessárias para o arquivo funcionar.
  • Textos e aparência da página: ficam em public/index.html e public/style.css. Essas partes não precisam ser alteradas para atualizar um preço ou uma foto.

Preço: altere o número depois de "price":. Use ponto para centavos (por exemplo, 21.8 representa R$ 21,80). Disponibilidade: depois de "available":, mantenha true para disponível ou false para indisponível. O nome e os textos ficam entre aspas: "summary" é a frase curta do produto e "description" é o texto completo que aparece ao abrir os detalhes.

Foto: na coluna esquerda, abra public → assets → chef-dani. Coloque a nova foto nessa pasta. No cadastro do produto, o campo "image": precisa ter o nome exato do arquivo, incluindo .jpg ou .png.

Salve com Ctrl + S. Volte ao navegador da prévia e atualize com Ctrl + R. Confira o produto e o preço antes de continuar.

Os produtos deste site são mantidos neste projeto. Alterações no InstaDelivery não aparecem automaticamente aqui; é preciso atualizar este arquivo também.

4
Só faça isso depois de revisar tudo

Enviar a versão aprovada para o site

Esta etapa muda o cardápio que os clientes veem. Antes de continuar, confira na prévia nomes, descrições, preços, fotos e disponibilidade. Quando estiver tudo certo, copie este comando, cole no Git Bash e pressione Enter:

./deploy.command

O Git Bash vai mostrar o andamento. Espere até aparecer ✓ Deploy concluído. Só então abra o site publicado ↗ e confirme se a mudança está lá.

“Build” quer dizer preparar os arquivos do site. Neste projeto, o comando acima já faz essa preparação e a publicação. Não é necessário rodar outro comando de build.

Se aparecer uma mensagem de erro ou não aparecer “Deploy concluído”, pare aqui: o site pode não ter sido atualizado. Copie a mensagem do Git Bash e peça ajuda. Se a mensagem disser que a Cloudflare não está conectada, siga a instrução “conectar à Cloudflare” na etapa 1.

5
Opcional

Consultar as estatísticas

Para ver quantas pessoas acessaram o cardápio e quais ações fizeram, abra o painel de estatísticas ↗ e entre com a senha administrativa. Se não tiver essa senha, peça-a à pessoa responsável pelo site.

Dentro do painel, escolha o período que quer consultar. Os números representam eventos registrados nesse intervalo.

Esqueceu a senha ou precisa ver os registros técnicos?

A senha pode ser alterada por quem tem acesso administrativo à conta Cloudflare. No Git Bash, dentro da pasta do projeto, rode o comando abaixo e digite a nova senha quando solicitado. Ela não aparece na tela enquanto você digita; isso é normal.

npx wrangler secret put ADMIN_PASSWORD

Para suporte técnico, os registros recentes podem ser vistos com:

npx wrangler tail cardapio

6
Para quem já usa GitHub

Sincronizar com o GitHub

O GitHub guarda uma cópia do projeto e seu histórico. Esta etapa é diferente de publicar o site. Se você já usa GitHub neste projeto, confira os arquivos alterados e depois envie as mudanças:

git status git add -A git commit -m "Atualiza produtos do cardápio" git push origin main

git status mostra o que mudou. git add -A seleciona essas mudanças para guardar. git commit registra uma cópia com o resumo escrito entre aspas. git push envia a cópia ao GitHub.

Neste projeto, enviar ao GitHub pode também iniciar uma publicação automática. Se não tiver certeza de que os arquivos listados em git status são os corretos, não continue; peça ajuda. A publicação manual é feita com ./deploy.command, na etapa 4.

Se o Git Bash disser “nothing to commit” ou “não há alterações”, não existe mudança nova para guardar. Isso não é um erro.
