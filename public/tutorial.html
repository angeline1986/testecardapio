Guia de atualização do cardápio

Atualize, confira e publique com tranquilidade.

Siga as etapas na ordem. Você vai abrir a pasta do projeto, alterar o cardápio, conferir a mudança numa cópia de teste e só então atualizar o site que os clientes acessam.

Ver as etapas ↓ Abrir estatísticas ↗
✦
Primeiro confira. Depois publique.

A prévia é uma cópia de teste no seu computador. O site público só muda quando você executa a etapa “Publicar”. Não há um comando separado para “build”.

⌘
Como usar os comandos deste guia

Cada caixa escura contém um comando. Clique em Copiar, clique na janela do Terminal, cole com Command (⌘) + V e pressione Enter. Espere o comando terminar antes de colar o próximo. Não cole comandos na barra de endereço do navegador.

1
Faça esta preparação uma vez em cada computador

Abrir a pasta do projeto

O Terminal é um aplicativo do Mac onde você cola comandos curtos para executar tarefas. Para abri-lo, pressione Command (⌘) + Espaço, escreva Terminal e pressione Enter.

Se este projeto já está no computador e dentro da pasta Documentos → TI → Projetos → testecardapio, clique em Copiar neste comando. Depois clique na janela do Terminal, cole o comando com Command (⌘) + V e pressione Enter:

cd "$HOME/Documents/TI/Projetos/testecardapio"

Esse comando só informa ao Terminal qual pasta usar. Ele não altera o cardápio.

Agora verifique se o computador está pronto. Copie, cole no Terminal e pressione Enter:

./setup_cardapio.command

O Terminal vai mostrar uma lista de itens com ✓. Se aparecer uma linha com ✗, a ferramenta indicada está faltando; peça ajuda para instalá-la antes de continuar. A prévia também precisa do Python 3.

O assistente fez uma pergunta e não sei o que responder

Se perguntar Configurar senha administrativa agora? [s/N], responda N se você não for a pessoa responsável pela senha do painel. Se for responsável, responda s e digite a nova senha quando solicitado; os caracteres não aparecem enquanto você digita, e isso é normal.

Se perguntar Executar validação/publicação do cardápio agora? [s/N], responda N por enquanto. A publicação tem uma etapa própria mais abaixo, depois da revisão da prévia.

Se informar que falta um segredo chamado SESSION_SECRET, não tente adivinhar um valor: peça ajuda à pessoa responsável pela conta Cloudflare antes de publicar.

Não tem a pasta do projeto no computador?

Use esta opção apenas se ainda não baixou o projeto neste computador. No Terminal, copie e execute um comando por vez, na ordem abaixo. O segundo comando entra na pasta que acabou de ser criada.

git clone https://github.com/angeline1986/testecardapio.git
cd testecardapio

Depois, execute ./setup_cardapio.command, mostrado acima. Se o primeiro comando disser que git não foi encontrado, o Git precisa ser instalado neste computador.

O Terminal diz que não está conectado à Cloudflare?

A Cloudflare é o serviço onde o site está publicado. Copie e execute o comando abaixo. Uma página abrirá no navegador: entre na conta Cloudflare responsável pelo cardápio e autorize o acesso. Depois volte ao Terminal e execute novamente ./setup_cardapio.command.

npx wrangler login
2
Faça isso sempre que for revisar mudanças

Conferir uma prévia do cardápio

Confirme que o Terminal ainda está usando a pasta testecardapio. Copie o comando, cole no Terminal e pressione Enter:

./preview.command

O navegador deve abrir uma página com o cardápio. O endereço começa com http://127.0.0.1; isso significa que você está vendo a cópia de teste no seu computador. Se o navegador não abrir sozinho, copie o endereço que apareceu no Terminal e cole-o na barra de endereço do navegador.

Depois de editar um arquivo, volte para essa página e atualize-a com Command (⌘) + R para ver a mudança. Mantenha o Terminal aberto enquanto estiver usando a prévia.

Para fechar a prévia: clique na janela do Terminal e pressione Control + C. Isso fecha só a cópia de teste; não publica nem apaga nada.

3
Salve o arquivo e confira a prévia depois de cada mudança

Atualizar produtos, fotos e aparência

Use um editor de código, como o Visual Studio Code. No VS Code, escolha File → Open Folder (Arquivo → Abrir Pasta), selecione a pasta testecardapio e clique em Open (Abrir). Os arquivos do projeto aparecem na coluna esquerda. Para atualizar um produto:

  • Na coluna esquerda, clique na seta ao lado de public e depois em products.json.
  • Pressione Command (⌘) + F, escreva o nome atual do produto e pressione Enter para encontrá-lo.
  • Altere apenas o texto ou número entre aspas indicado abaixo. Não apague aspas, vírgulas ou chaves: elas são necessárias para o arquivo funcionar.
  • Textos e aparência da página: ficam em public/index.html e public/style.css. Essas partes não precisam ser alteradas para atualizar um preço ou uma foto.

Preço: altere o número depois de "price":. Use ponto para centavos (por exemplo, 21.8 representa R$ 21,80). Disponibilidade: depois de "available":, mantenha true para disponível ou false para indisponível. Nome e descrição são textos entre aspas.

Foto: na coluna esquerda, abra public → assets → chef-dani. Coloque a nova foto nessa pasta. No cadastro do produto, o campo "image": precisa ter o nome exato do arquivo, incluindo .jpg ou .png.

Salve com Command (⌘) + S. Volte ao navegador da prévia e atualize com Command (⌘) + R. Confira o produto e o preço antes de continuar.

Os produtos deste site são mantidos neste projeto. Alterações no InstaDelivery não aparecem automaticamente aqui; é preciso atualizar este arquivo também.

4
Só faça isso depois de revisar tudo

Enviar a versão aprovada para o site

Esta etapa muda o cardápio que os clientes veem. Antes de continuar, confira na prévia nomes, descrições, preços, fotos e disponibilidade. Quando estiver tudo certo, copie este comando, cole no Terminal e pressione Enter:

./deploy.command

O Terminal vai mostrar o andamento. Espere até aparecer ✓ Deploy concluído. Só então abra o site publicado ↗ e confirme se a mudança está lá.

“Build” quer dizer preparar os arquivos do site. Neste projeto, o comando acima já faz essa preparação e a publicação. Não é necessário rodar outro comando de build.

Se aparecer uma mensagem de erro ou não aparecer “Deploy concluído”, pare aqui: o site pode não ter sido atualizado. Copie a mensagem do Terminal e peça ajuda. Se a mensagem disser que a Cloudflare não está conectada, siga a instrução “conectar à Cloudflare” na etapa 1.

5
Opcional

Consultar as estatísticas

Para ver quantas pessoas acessaram o cardápio e quais ações fizeram, abra o painel de estatísticas ↗ e entre com a senha administrativa. Se não tiver essa senha, peça-a à pessoa responsável pelo site.

Dentro do painel, escolha o período que quer consultar. Os números representam eventos registrados nesse intervalo.

Esqueceu a senha ou precisa ver os registros técnicos?

A senha pode ser alterada por quem tem acesso administrativo à conta Cloudflare. No Terminal, dentro da pasta do projeto, rode o comando abaixo e digite a nova senha quando solicitado. Ela não aparece na tela enquanto você digita; isso é normal.

npx wrangler secret put ADMIN_PASSWORD

Para suporte técnico, os registros recentes podem ser vistos com:

npx wrangler tail cardapio

6
Para quem já usa GitHub

Sincronizar com o GitHub

O GitHub guarda uma cópia do projeto e seu histórico. Esta etapa é diferente de publicar o site. Se você já usa GitHub neste projeto, confira os arquivos alterados e depois envie as mudanças:

git status git add -A git commit -m "Atualiza produtos do cardápio" git push origin main

git status mostra o que mudou. git add -A seleciona essas mudanças para guardar. git commit registra uma cópia com o resumo escrito entre aspas. git push envia a cópia ao GitHub.

Neste projeto, enviar ao GitHub pode também iniciar uma publicação automática. Se não tiver certeza de que os arquivos listados em git status são os corretos, não continue; peça ajuda. A publicação manual é feita com ./deploy.command, na etapa 4.

Se o Terminal disser “nothing to commit” ou “não há alterações”, não existe mudança nova para guardar. Isso não é um erro.
