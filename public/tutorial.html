Guia rápido do projeto

Do ajuste à publicação, passo a passo.

Use este guia para abrir o projeto no computador, editar produtos, conferir a prévia e publicar o cardápio na Cloudflare.

Começar pelo início ↓ Abrir estatísticas ↗
✦
Não existe um build separado.

O Wrangler prepara os arquivos quando você publica. Para revisar localmente, use a prévia; para enviar ao site, use ./deploy.command.

1. Preparar2. Rodar localmente3. Editar conteúdo4. Validar e publicar5. Acompanhar6. GitHub
1

Preparar o computador

Você precisa de Node.js/npm, Python 3, Git e acesso à conta Cloudflare do Worker cardapio. Abra o Terminal e entre na pasta do projeto.

cd ~/Documents/TI/Projetos/testecardapio ./setup_cardapio.command

Se ainda não clonou o projeto, use estes comandos primeiro:

git clone https://github.com/angeline1986/testecardapio.git cd testecardapio

Na primeira configuração, o assistente pode pedir que você entre na Cloudflare. Se precisar fazer isso manualmente:

npx wrangler login npx wrangler whoami
2

Rodar uma prévia no computador

Na pasta do projeto, execute o comando abaixo. O navegador abrirá uma cópia local do site. Deixe o Terminal aberto enquanto confere as alterações; use Ctrl+C para encerrar.

./preview.command

A prévia local não publica nada. Ela serve para conferir o resultado antes de enviar ao site.

3

Editar produtos e imagens

  • public/products.json: nomes, descrições, categorias, preços e disponibilidade.
  • public/assets/chef-dani/: fotos dos produtos. Atualize também o campo image no catálogo.
  • public/index.html, public/style.css e public/script.js: estrutura, aparência e interações.

Depois de salvar, rode novamente ./preview.command e confira em uma tela de computador e em um celular.

O catálogo é mantido neste projeto. Alterações no InstaDelivery não atualizam automaticamente os preços ou a disponibilidade daqui.

4

Validar e publicar

Quando a prévia estiver certa, publique com o script. Ele verifica os arquivos, confere a autenticação Cloudflare, faz uma validação de deploy e então publica.

./deploy.command

O site publicado fica em cardapio.chefdaniteles.workers.dev. Não é preciso rodar npm install nem npm run build para este projeto.

Se aparecer erro de autenticação, execute npx wrangler login e depois tente o deploy novamente.

5

Ver estatísticas e logs

O painel de estatísticas exige a senha administrativa configurada na Cloudflare:

Abrir o painel de estatísticas ↗

Para acompanhar logs do Worker pelo Terminal:

npx wrangler tail cardapio

Para conferir quais secrets estão configurados, sem revelar os valores:

npx wrangler secret list --config wrangler.jsonc

Para trocar a senha do painel, rode npx wrangler secret put ADMIN_PASSWORD e informe a nova senha no Terminal. A Cloudflare aplica essa alteração imediatamente. Nunca salve senhas no projeto ou no Git.

6

Salvar as alterações no GitHub

Depois de revisar o que mudou, registre e envie as alterações:

git status git add -A git commit -m "descreva a alteração" git push origin main

Leia a saída de git status antes de adicionar os arquivos. O Worker pode estar conectado ao deploy automático do GitHub; nesse caso, um push para main também pode publicar. O script ./deploy.command faz o deploy manual.
